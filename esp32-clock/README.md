# esp32-clock — 桌面日程时钟

微雪 ESP32-S3-Touch-LCD-1.54（240×240 触摸屏）上的桌面时钟：暖白界面 + 钉钉日程 +
天气 + 农历。日程数据来自配套的 [esp32-dingtalk-bridge](../esp32-dingtalk-bridge)。

当前固件 **v2.0 暖白双模式**（日常 / 极简），v1 青绿圆环版备份在
`backup/v1-green-ring-20261103/`。

**坐标、颜色、字号全部照抄固件**，改界面前先在这里调，不用烧板子。

| 手势 | 点屏幕（夜间提亮 30 秒、熄屏点亮）· 长按 0.65 秒切模式 · 左右滑切卡片 |

## 日程的生命周期

首页那张卡片只显示「还没开完」的日程，状态分三种：

| 卡片右上角 | 含义 |
|---|---|
| `23 分钟后` | 还没开始 |
| `已开始` | **正在进行**（开始时间已过，结束时间未到） |
| `全天` | 全天日程 |

**开完之后会自动消失**（每分钟检查一次）。判断依据是推送器算好的时长
（钉钉的 `end - start`），所以一场 16:00–18:00 的会，17 点还显示「已开始」
是正确的，18:00 才撤掉。拿不到时长时按 60 分钟兜底。

> ⚠️ 早先的版本倒计时归零后就**停在 0 不动、卡片永不消失** ——
> 结果第二天首页还挂着昨天的会。这就是加 `durationMin` 的原因。

## 三个界面与手势

| 界面 | 操作 |
|---|---|
| 主屏 | 左右滑动切换日程卡片 · 单击进日程列表 · **点天气栏右侧的桌宠进宠物页** · **长按 0.65 秒切换日常/极简** |
| 提醒弹窗 | 日程开始前 10 分钟弹出（**同时响提示音**）· **点任意位置都能关**（右下角才是「到点再叫我」）· 按任意物理键也能关 · 最多停留 3 分钟 |
| 日程列表 | 一页 5 条，每行 `月-日 时间`，按日期时间排序 · **上下滑动翻页** · 点按返回 |
| 宠物页 | 点猫或「逗它」= 逗它 · 「喂食」= 吃 + 咀嚼动画 · **只有「返回」能退出**（点空白无反应） |

**没有设置页**：调音量时顶部弹出深色胶囊（`音量 60%` + 进度条），1 秒后自动消失，
不切屏、不打断当前界面。

极简模式、音量、声音开关都存在 NVS（`clockui` 命名空间），重启后保持。

弹窗规则：未确认不自动消失（**但有 3 分钟兜底，避免触摸失灵把时钟锁死**）；
日程已开始未确认则不再弹；全天日程不弹窗。

> 点击判定用的是**按下点**，不是抬指点 —— 抬指那一帧的坐标常常是 `0,0` 或抖动值，
> 用它做命中会出现「点了完全没反应」。这是 v2.1 卡在提醒页的根因。

## 桌宠

天气栏**最右侧**有一只 15×13 的像素猫（scale 2，30×26，贴右边缘）。

- **点它** → 进宠物页；**点屏幕其它位置** → 还是原来的日程列表
- 宠物页：左上大字时间 + 右上日期 → 气泡 → 大号桌宠（scale 4）→
  下一日程 → 三个按钮（`喂食` / `逗它` / `返回`）
- 点猫本身也算「逗它」；**点空白处什么都不做** ——
  宠物页只能靠「返回」退出，免得摸一下空白就跳走看不到猫

### 自动动作

| 动作 | 触发 |
|---|---|
| 眨眼 | 每 2.4~5 秒一次，闭 150ms |
| 摆尾 | 每 520ms 换一档（上/下） |
| 犯困 | **20:00~09:00** 自动闭眼（正在吃/玩时先不打断） |
| 咀嚼 | 喂食后 1.6 秒，嘴一张一合 |
| 跳跃摆尾 | 逗它 1.3 秒，尾巴每 120ms 甩一下 |

心情会影响气泡文案：`谢谢！好吃～` / `嘿嘿，再来一次` / `有点困了，早点休息`，
30 分钟内有日程时显示 `快到点了，别忘了`，其余 `今天也陪你一起工作`。

### 实现要点

- 位图只有身体（`PET_ROWS[13]`），**眼睛/嘴/尾巴单独画** ——
  眨眼、摆尾不用存多份位图，改表情就是换几个 `fillRect`
- 动画只重绘桌宠那一小块并推一条带（`flushBand(164,28)`），不整屏刷
- 天气文案和城市行的宽度让出了右侧 194~224 给桌宠

调试（不开触摸也能试）：

```bash
# 串口直接发
PET|open    # 打开宠物页
PET|feed    # 喂食
PET|play    # 逗它
PET|back    # 返回
PET         # 查当前心情/喂食次数
```

`STATE` 里也有一行 `STATE|pet|<心情>|<眨眼>|<尾巴>|<喂食次数>`
（心情 0 空闲 / 1 高兴 / 2 吃 / 3 玩 / 4 困）。

## 声音与音量

板子上**没有无源蜂鸣器**，声音走 `ES8311 编解码器 → 功放(PA_CTRL) → 板载喇叭`，
由 I2S 数字输出。所以提示音不是「GPIO 拉高响一下」，需要初始化 codec。

实现见 `firmware/esp32-clock/audio.{h,cpp}`：

- I2S 主机模式，16 kHz / MCLK 4.096 MHz（256×fs），ES8311 走从机
- codec 控制复用触摸那条 I2C（SDA42 / SCL41，地址 `0x18`）
- 正弦波带 5 ms 淡入淡出，避免爆音；音量同时调 codec 的 DAC 寄存器（0x32）

| 触发 | 声音 |
|---|---|
| 提醒弹窗出现 | 三声上行 `880 → 1175 → 1568 Hz`，约 0.55 秒 |
| 弹窗一直没处理 | 每 30 秒补一次，**最多 3 次** |
| 调音量（按键/串口） | **880 Hz 试听音 250 ms** —— 频率/幅度与提醒音的第一个音一致，听到的响度就是提醒的响度，用来判断音量是否合适 |
| 切声音开关 | 1760 Hz 短促一声（35 ms） |
| 「试听提示音」 | 与弹窗完全相同 |

音量控制有两个入口，都写同一份 NVS，都会弹同一个浮层：

| 入口 | 步进 |
|---|---|
| GPIO4（音量+）/ GPIO0（音量−） | 5% |
| GPIO5 | 静音 / 恢复 |
| 串口 `VOL\|60` / `SND\|1` / `BEEP` | 任意值 / 开关 / 立即试听 |

浮层：`132×40` 深色胶囊，居中在 `y=6`，文字 + 4px 进度条，`VOL_TOAST_MS = 1000`。
只刷顶部 48 行（`flushBand(0,48)`），不整屏重绘；到期后整屏重绘一次擦掉。

> 按键映射不是猜的：用 `hook/key-scan.py` 逐个按出来的（见下方「按键排查」）。
>
> ⚠️ GPIO0 是 ESP32-S3 的 strapping 脚，**开机瞬间按住音量−会进下载模式**。
> 正常使用（开机后再按）没有影响。
>
> 浏览器预览：[`simulator/volume-toast-preview.html`](simulator/volume-toast-preview.html)
> 点按钮看浮层效果，并用 WebAudio 听到与固件同样频率的提示音。

## 背光：夜间调光与熄屏

背光 GPIO46 走 LEDC PWM（5 kHz / 8bit），两套自动行为：

| 行为 | 触发 | 效果 |
|---|---|---|
| **夜间调光** | 每天 **20:00 ~ 次日 09:00**（按设备 RTC 判断） | 亮度降到约 12%（`BL_NIGHT 30/255`） |
| **夜间临时提亮** | 夜间触碰屏幕或按任意键 | 恢复全亮 **30 秒**，到期自动暗回去 |
| **熄屏** | **长按静音键（GPIO5）0.8 秒** | 背光 0，画面仍在显存里 |
| **点亮** | 熄屏时触摸屏幕或按任意键 | 点亮 + 按夜间规则提亮 30 秒 |

要点：

- 夜间判断用设备自己的 RTC —— USB 对时、NTP、演示时钟都能走，**断线也正确切换**
- 熄屏时那次触摸/按键**只负责点亮**，不触发手势、不切静音 ——
  否则点亮屏幕的同时会误改音量或弹日程列表
- 长按熄屏与短按静音的区分靠松键判定：按住超 0.8 秒直接熄屏，
  不足 0.8 秒松开才算静音切换
- `ledcAttach` 失败会退回直连全亮（功能退化但不黑屏）
- 时间来源没有就绪时（刚开机几秒）按白天处理，loop 每轮都会重算，无影响

调试：白天测夜间效果不用等到 20:00：

```bash
python3 hook/serial_push.py --bl 12    # 固定 12% 亮度（看夜间效果）
# 或直接发串口命令：BL|12（固定）/ BL|auto（恢复自动）
```

`STATE` 回读里也带一行 `STATE|bl|<级别>|<HH:MM>|<夜间?>|<熄屏?>`，
不用盯屏幕就能确认当前背光状态。

## 电量显示

顶栏从左到右：**日期周几 → 数据来源徽章 → 电量**。

```
11月04日 周三          USB        ⚡ 71%
└─ 最宽 92px ─┘   └112~154┘   └168~222┘
```

- 来源徽章（`USB` / `WIFI` / `LOCAL` / `DEMO`）原来占着最右边，
  把电量位置挤没了；现在徽章挪到电量前面，电量占最右
- 电量 = **电量条 + 百分比**，三种状态：
  **充电中**（实心绿底 + 近白闪电）· **已充满**（实心绿底满格）·
  **放电中**（灰色，低于 25% 转陶橙）
- 每 30 秒采一次，**只有状态变了才重绘**（避免整屏闪）

> ⚠️ 闪电必须用 `C_BG`（近白）画。这个主题的 `C_TEXT` 是深灰，
> 画在深色底上等于看不见 —— 第一版就是从 wb-status 的深色主题抄来的，
> 结果「插着 USB 却看不出在充电」。

### 充满之后为什么显示「没在充电」

**这是充电器正常的截止行为，不是故障。**

锂电池充到 4.2V 后，板上的充电 IC 会自己终止充电（CV 阶段结束），
并把 `CHG_STAT` 从低电平释放成高电平 —— 固件读到的就是「没在充电」。
静置后电压会从 4.2V 回落到 4.1~4.15V，属正常现象。

所以固件把「插着电 + 电压 ≥4.10V + CHG_STAT 高」判定为**已充满**，
显示实心绿底满格（没有闪电），和「拔了线在放电」区分开：

| 界面 | 含义 |
|---|---|
| 绿底 + 闪电 | 正在充电（CHG_STAT 低） |
| 绿底满格、无闪电 | **已充满**（充电器已截止） |
| 灰色/陶橙、按电量填充 | 放电中（未接 USB 或已拔出） |

另外 4.15V 以上直接算 100% —— 否则充完显示 95% 会让人觉得「怎么充不满」。

### 采样与分压比（重要）

引脚同 wb-status：`BAT_ADC=GPIO1`（ADC1，不受 WiFi 占用 ADC2 影响）、
`CHG_STAT=GPIO3`（低电平=充电中）、`BAT_EN=GPIO2`。

**分压比是 3.0，不是 2.0** —— 这是实测推出来的，不是抄的：

| 证据 | 推论 |
|---|---|
| ADC 原始读数稳定在 **1.294V** | 分压后电压，不是噪声 |
| 设备靠电池独立跑了一整夜 | 电池实际电压必然 ≥ 3.0V（锂电保护约 2.8V） |
| 按 2.0 折算只有 2.59V | 与「跑了一整夜」矛盾 → 分压比不可能只有 2.0 |
| 按 3.0 折算是 3.88V（约 66%，充电中） | 与事实吻合 → 板上是 200k+100k 分压 |

> 所以抄别的板子的 `BAT_DIV 2.0` 会让电量一直显示 0%。换板子/换批次先跑
> `BAT` 命令核对原始毫伏，再决定 `BAT_DIV`。

调试命令：串口直接发 `BAT`，会立刻重采并打印原始数据：

```
BAT|1384|4.15|100|0|1   # 原始毫伏 | 折算电压 | % | 充电中 | 已充满
```

`STATE` 里也有一行 `STATE|bat|<百分比>|<充电?>|<充满?>`，
以及 `STATE|demo|<0/1>`（1 = 屏上还是开机注入的演示数据）、
`STATE|link|<0/1>|<距上次收到数据的毫秒数>`（顶栏 `USB`/`LOCAL` 的依据）、
`STATE|wx|<温度>|<过期?0/1>|<该温度所属日期>`（判断天气是否已超出三天缓存）。

## 运行模式

| 模式 | 条件 | 行为 | 顶栏标识 |
|---|---|---|---|
| **USB 模式**（推荐） | Mac 上跑 `hook/serial_push.py` | 时间与日程由 Mac 通过数据线推过来，**不需要 WiFi** | 蓝色 `USB` |
| 联网模式 | 填好 WiFi 与 `BRIDGE_BASE` | NTP 对时（阿里云）+ 每 60 秒轮询桥接 | 绿色 `NTP` |
| 演示模式 | 以上都没有 | 本地时钟 + **4 条内置演示日程**，点按切换 | 橙色 `DEMO` |

优先级 USB > WiFi。USB 连续 **45 秒**没有数据才回落（Mac 端每 15 秒一个 `PING` 心跳）。

### 演示数据（内置的 4 条假日程）

`initDemoEvents()` 会塞 4 条硬编码日程：`备赛课二期提测` / `new-api 每日签到` /
`课程组周会` / `版本上线窗口`，外加假天气（22° 晴 · 北京·朝阳）和假农历。

**它们只在「完全独立运行的裸板」上有意义** —— 让人一眼看到界面长什么样。
所以一旦 Mac 开始喂真实数据（`TIME` / `EVENTS` / `NONE` / `WEATHER` / `DAYS` 等），
`dropDemoData()` 会**把演示日程和演示天气整体撤掉**，屏幕回到
「今日无日程」+「天气暂未同步」。

> ⚠️ 这是个真实踩过的坑：演示日程看起来和真日程一模一样（标题都是项目名）。
> 早期版本只把 `demoMode` 置 false，**却没有清空已注入的 `events[]`** ——
> 于是桥接没跑、或者日历里没有日程的时候，屏幕上会一直挂着这 4 条假日程冒充真日程。
> 现在 `STATE|demo|1` 可以直接看出屏上是不是演示数据。

### USB 模式怎么用

```bash
# 1. 桥接（提供日程数据）
cd ../esp32-dingtalk-bridge && .venv/bin/python bridge.py

# 2. 串口推送（提供时间 + 日程）
cd ../esp32-clock && python3 hook/serial_push.py
```

`serial_push.py`：

- 每 60 秒推 `TIME|<epoch>` —— **没 WiFi 就没有 NTP，这是唯一时间来源**
- 每 **15 秒**推 `PING` 心跳 —— 设备靠它判断「Mac 还在」，顶栏才能稳定显示 `USB`
- 每 5 秒推 `EVENTS|<n>` + n 条 `EV|…`（日程变了才推）
- 每 5 分钟推 `WEATHER|…` + `DAYS|3` + 3 条 `DAY|…`（天气/农历变了也推）
- 推完三天会**回读设备实际存了几条**，对不上自动重推

> ⚠️ **心跳间隔必须小于设备端的链路超时**。设备 45 秒收不到任何数据就切 `LOCAL`。
> 早期没有心跳、只靠 60 秒一次的 `TIME` —— 结果每隔一分钟有半分钟显示 `LOCAL`，
> 看起来像「插着 USB 却掉线了」。

### 插拔 USB 会发生什么

推送器是常驻的，**插上就自动同步，拔掉也不影响走时**：

| 场景 | 行为 |
|---|---|
| 设备已插着才启动推送器 | 正常连接，第一轮就把 对时 + 日程 + 天气 + 三天 全推一遍 |
| **先启动推送器，再插 USB** | 推送器每 2 秒找一次设备，插上瞬间自动开始同步（不再报错退出） |
| **使用中拔掉 USB** | 时钟照常走（RTC 自己走），三天缓存继续按日期切换；推送器安静等待，**不刷屏** |
| **重新插上** | 2 秒内重连，**清空全部推送状态、立即全量补推** —— 就算设备断电重启过（缓存空了）也能立刻补齐，不用等 5 分钟天气间隔 |
| 拔线超过 45 秒 | 屏幕顶栏 `USB` 变 `LOCAL`，插回来 2 秒内变回 `USB`（靠 15 秒一次的心跳） |

> 实测：推送器常驻 16 小时、设备拔线一整晚，插回后 2 秒重连，
> 三天缓存立即从 `11-03/04/05` 刷成 `11-04/05/06`，
> 期间设备端 LOCAL 模式过 0 点自动切换、RTC 走时一秒不差。

想让 Mac 开机就自动同步的话，把推送器做成登录项（`系统设置 → 通用 → 登录项`
加一个 shell 脚本，或 launchd plist），它没找到设备也会一直等。

### USB 模式能拿到什么

固件里天气和农历都有 USB 路径（`WEATHER` / `DAYS`+`DAY`），走 USB 时：

| 元素 | 现状 |
|---|---|
| 时间 | ✅ 正常（Mac 每 60 秒推 `TIME`） |
| 日程 | ✅ 全部（`EVENTS` + `EV` 批量推，最多 8 条） |
| 天气 | ✅ 桥接的 `/api/weather`，5 分钟一次 |
| 农历 | ✅ 跟天气一起推 |
| **未来三天** | ✅ 每次推送都带 3 天的「日期 / 周几 / 农历 / 天气 / 空气质量」 |

### USB 拔掉之后

时钟继续正常走时，**不依赖 USB 存活**：

- 时间：`TIME` 写进系统 RTC 后由芯片自己走，拔线不影响
- 日程 / 天气：保留最后一次收到的内容（可能过期，但不会消失也不会崩）
- **三天数据表**：每次推送带未来 3 天的「日期 / 周几 / 农历 / 天气」，
  设备按当前日期自动挑对应的那天。**过 0 点整屏重绘一次，自动切到下一天**，
  断线状态下也能正确显示农历和天气（约可撑 3 天）
- **超出 3 天**（离线太久）：周几退回设备本地推算，**农历清空**，
  **天气改为显示「天气数据已过期」** —— 这三样都和日期绑死，留着过期的就是错的。
  注意天气只是**隐藏**（`weatherStale` 标志），数据仍留着：
  时钟一拨回缓存范围内就立刻恢复，不用等下一次推送
- 顶栏来源标识：45 秒收不到数据从 `USB` 变成 `LOCAL`
- 串口写改成非阻塞（`setTxTimeoutMs(0)` + `DBG()` 宏），
  拔线后日志直接丢弃，**不会因为 TX 缓冲满把主循环卡死**
- 提醒弹窗最多停留 3 分钟，避免任何情况下锁死界面

### 三天缓存的原理

固件里存一张三行的表，`applyDayFor()` 按今天的 `MM-DD` 挑行：

```cpp
#define MAX_DAYS 3
DayInfo days[MAX_DAYS];   // 每行：日期 / 周几 / 农历 / 温度 / 文案 / 图标 / 空气质量
```

- 推送时 `DAYS|3` 声明条数，后面跟 3 条 `DAY|…`
- 每次渲染都按当前日期重新挑一次 —— 所以「过 0 点自动切换」不需要定时器，
  下一次刷新自然会切
- 换日判断用**完整的 `YYYYMMDD`**（不是只比 `tm_mday`），跨月才不出错
- 只有 `LUNAR|`（没有三天表）的老路径保留原样，不会被清空

### 缓冲区大小

中文全是 3 字节/字，缓冲区按**字节**算，不能按字数估：

| 字段 | 大小 | 能装几个汉字 |
|---|---|---|
| `weatherText` | 32 字节 | 10 个 |
| `cityText` | 32 字节 | 10 个 |
| `aqiText` | 24 字节 | 8 个 |
| `lunarText` | 48 字节 | 16 个（`乙巳蛇年 · 十一月廿四` = 31 字节） |
| `days[i].lunar` | 48 字节 | 同上 |

截断必须**按字符边界**，不能按字节边界。`strlcpy()` 会在字节边界截断，
中文一个 3 字节 —— 切一刀就劈成半个汉字，屏幕上是乱码或者豆腐块。
固件里统一用 `copyUtf8()`：

```cpp
// 按 UTF-8 字符边界截断，绝不劈开半个汉字
size_t copyUtf8(char *dst, size_t cap, const char *src) {
    if (!cap) return 0;
    size_t n = 0;
    while (src[n] && n + 1 < cap) {
        size_t clen = utf8CharLen(src[n]);
        if (n + clen >= cap) break;       // 下一个字符放不下就停
        for (size_t i = 0; i < clen; i++) dst[n + i] = src[n + i];
        n += clen;
    }
    dst[n] = 0;
    return n;
}
```


esp32 core 3.3.12。

### USB CDC 缓冲区必须显式加大

⚠️ 这是踩过最隐蔽的坑。ESP32-S3 的 `HWCDC` 类**收发队列默认各只有 256 字节**，
超出的字节**静默丢弃**，不报错、不崩，表现为「某几条数据没进去」。

一次完整推送（`TIME` + `EVENTS` + 4 条 `EV` + `WEATHER` + `DAYS` + 3 条 `DAY`）
大概 430~500 字节，**直接超了 256**。实测：发 50 个 `PING`（250 字节）全部收到，
发 80 个（400 字节）只剩 51 个 —— 29 个凭空消失。

固件里必须在 `begin()` **之前**设置（`begin()` 只在队列为空时才用默认值创建）：

```cpp
void setup() {
    Serial.setRxBufferSize(1024);   // 默认 256，装不下一次完整推送
    Serial.setTxBufferSize(1024);
    Serial.begin(115200);
    Serial.setTxTimeoutMs(0);       // 写不出去立刻返回，绝不阻塞主循环
    delay(200);
}
```

Mac 端也有两道保险（`serial_push.py`）：

- `send_batch()`：逐行发，每行之间留 12ms，等设备回 `OK` 再发下一行
- `push_days()`：推完三天**回读设备实际存了几条**，对不上自动重推一次

所以以后推新字段，记住两件事：**固件里加 `setRxBufferSize`，Mac 端分批发**。

## 渲染方式

整帧画进 PSRAM 离屏画布（`PsramCanvas`），再按需推屏：

```cpp
gfx->flush();                              // 整屏
gfx->flushBand(41, 108);                   // 只推某一段，用于走秒
```

分带刷新的原因：秒数每秒变一次，整屏推一次约 25ms；只推变化的那几十行可以省下
大部分带宽，也避免整屏闪。

> v1 用的是「局部擦除 + 局部重绘」，踩了三个擦除 bug（四角线框被擦掉、青色虚线与
> 圆环同半径被抹、秒点圆啃刻度）。改成画布后这些都不存在了——见 `backup/` 里的 v1 代码。

## 踩坑记录

- **GFX 1.6.0 与 esp32 core 3.3.12 不兼容**（`spiFrequencyToClockDiv` 签名变更），
  必须 1.6.9+；官方 demo 包内置的是 1.6.0，别直接用
- **烧录末尾 `Serial data stream stopped / exit status 2`**：S3 原生 USB 复位
  重新枚举导致，写入与校验其实已成功，无视即可
- **烧完板子不启动**：USB-Serial/JTAG 不吃 RTS 复位，必要时补
  `esptool --after hard_reset chip_id`
- 中文显示：GFX 直接 `setFont(u8g2_font_wqy12_t_gb2312)` + `setUTF8Print(true)`；
  大数字用 `u8g2_font_logisoso42_tn`，中文标题用 `wqy16`
- **RGB565 深色陷阱**：低于 `(16,16,16)` 的颜色基本塌缩成黑，深色卡片色不要低于 `#181A1E`
- **CST816 必须硬复位**：只 `Wire.begin()` 不复位（GPIO47 拉低 10ms 再拉高），
  I2C 会应答但寄存器全是 0 —— 表现是「触摸完全没反应，且不报错」
- **caldav 2.x 不再自带 vobject**：缺了它 `item.vobject_instance` 恒为 `None`，
  所有日程解析失败、整次同步抛异常，桥接返回 0 条。`pip install vobject` 即可
- **USB CDC 收缓冲默认 256 字节**，一次完整推送超了就被静默丢弃 ——
  详见上面「USB CDC 缓冲区必须显式加大」
- **`strlcpy()` 会从字节边界截断**，中文一个 3 字节，切一刀就是半个汉字 ——
  一律用 `copyUtf8()` 按字符边界截断
- **`tm_mday` 判换日跨月会错**：用完整的 `YYYYMMDD` 当日期键
- **setup() 里用 `nowEpoch()` 前必须先把 `baseEpoch` 赋好**：`nowEpoch() =
  baseEpoch + 走时`，`baseEpoch` 还是 0 时算出来是 1970 年早上 8 点 ——
  背光初版因此被误判成夜间，白天开机带着 12% 亮度熬过整个 WiFi/NTP
  窗口（最长 25 秒）。任何依赖「当前时间」的初始化都要排在时钟起点之后
- **电池分压比抄别的板子会一直是 0%**：这块板是 1/3（200k+100k），
  按 1/2 折算只有 2.59V，落在「锂电已空」区间。判断办法不是看图纸而是看事实：
  设备能靠电池跑一夜，电压就不可能低于 3.0V

## 已知限制

1. **`BRIDGE_BASE` 是硬编码 IP** —— Mac 换网络后要重新烧录，建议路由器绑定静态 IP
2. **提示音只有一种** —— 固定三声上行，不区分「10 分钟后」和「已开始」
3. **离线超过 3 天没有农历** —— 三天缓存用完了，农历跟日期绑死，宁可空着也不显示错的
